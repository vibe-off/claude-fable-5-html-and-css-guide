# 层叠、优先级与继承

“我明明写了样式，为什么没生效？”——回答这个问题，靠的就是本节内容。这也是 CSS 最容易被低估、面试最爱考的部分。

## 冲突是常态

多条规则命中同一个元素、设置同一个属性时，浏览器按以下顺序裁决：

1. **来源与重要性**：`!important` > 普通声明（先不展开）
2. **优先级（Specificity）**：选择器越“具体”越强
3. **源码顺序**：以上都相同时，后写的赢

## 优先级的计算

把选择器的组成拆成三档，形成一个类似“百位-十位-个位”的三元组 `(a, b, c)`：

| 档位 | 计数对象 | 例子 |
| --- | --- | --- |
| a | id 选择器 | `#header` |
| b | 类、属性、伪类 | `.card`、`[type="text"]`、`:hover` |
| c | 元素、伪元素 | `p`、`::before` |

比较时从高位到低位，高位大者直接胜出：

```css
p { }                  /* (0,0,1) */
.intro { }             /* (0,1,0) 胜过任意多个元素选择器 */
p.intro { }            /* (0,1,1) */
#main p { }            /* (1,0,1) */
```

```css
/* 谁生效？ */
#main p {
  color: blue; /* (1,0,1) → 胜 */
}
.article .intro {
  color: red; /* (0,2,0) */
}
```

记住两个要点：

- **行内样式**（`style="..."`）比任何选择器都强。
- **通配符 `*` 和继承来的样式**优先级最低。

## !important：最后的手段

```css
p {
  color: red !important; /* 压过一切普通声明 */
}
```

::: danger 慎用 !important
它会引发“军备竞赛”：为了覆盖一个 `!important`，只能写另一个 `!important`。样式没生效时，正确做法是打开 DevTools 搞清楚**被谁覆盖了**，然后用一个优先级稍高的合理选择器解决，而不是甩一个 `!important` 了事。合理的使用场景几乎只有：覆盖无法修改的第三方样式。
:::

## 继承

有些属性会自动从父元素传给子元素——主要是**文字类属性**：

| 会继承 | 不会继承 |
| --- | --- |
| `color`、`font-*`、`line-height`、`text-align`、`letter-spacing` | `width`、`height`、`margin`、`padding`、`border`、`background` |

这就是为什么给 `body` 设置字体，整个页面都生效：

```css
body {
  font-family: sans-serif;
  color: #333;
  line-height: 1.6;
}
```

判断技巧：**文字排版属性大多继承，盒子和布局属性一律不继承**（想象一下 padding 如果继承会有多可怕）。

### 显式控制继承

```css
.child {
  color: inherit;  /* 强制继承父元素的值（如让链接颜色跟随正文） */
  color: initial;  /* 恢复属性的默认值 */
}
```

## 实战排查流程

样式没生效时，按这个顺序检查（DevTools 的 Styles 面板全程可见）：

1. **选择器选中元素了吗？** 没选中 → 检查选择器和 class 拼写。
2. **属性被划横线了吗？** 被划线 → 看是哪条更高优先级的规则覆盖了它。
3. **属性名旁有黄色警告吗？** 有 → 属性名或值写错了。
4. **值是继承来的吗？** Computed 面板能看到每个属性的最终值和来源。

## 练习

1. 不看答案，计算这几个选择器的优先级三元组：`nav ul li`、`.menu > li.active`、`#app .btn:hover`、`header nav a`。
2. 构造一个“样式被覆盖”的现场：用 `.text` 设置蓝色，用 `p.text` 设置红色，在 DevTools 里观察被划横线的声明。
3. 页面上放一个链接，让它的颜色跟随正文颜色（提示：`inherit`），悬停时才变成蓝色。
