# 开发者工具与调试

浏览器开发者工具（DevTools）是前端工程师**使用频率最高的工具**，没有之一。“会不会用 DevTools”几乎可以直接区分能不能干活。本节以 Chrome/Edge 为例。

## 打开方式

- `F12`，或 `Ctrl + Shift + I`（macOS：`Cmd + Option + I`）
- **右键页面元素 → 检查**：直接定位到该元素，最常用的入口

## Elements 面板：HTML 与 CSS 的手术台

### 左侧：DOM 树

显示浏览器**实际渲染**的结构（不是你写的源码——还记得浏览器会“修复”错误嵌套吗？两者的差异往往就是 Bug 所在）。

- 点击左上角的**箭头图标**再点页面任意元素，即可选中它
- 双击标签名、属性可以直接编辑
- 按 `Delete` 删除元素、拖动调整位置——都只影响当前页面，刷新即恢复

### 右侧：Styles 面板

选中元素后，这里列出**命中它的所有 CSS 规则**，按优先级从高到低排列：

| 你看到的 | 含义 |
| --- | --- |
| 声明被划横线 | 被更高优先级的规则覆盖了 |
| 属性名旁有黄色警告 | 属性名或值无效（多半是拼写错误） |
| 规则右上角的 `文件名:行号` | 这条规则写在哪里，点击可跳转 |
| `element.style` | 行内样式 |

**可以直接编辑**：点击任何值改掉它、点击色块打开取色器、勾选/取消勾选某条声明——页面实时变化。调样式的正确工作流是：**在 DevTools 里试到满意，再把值抄回源码**，而不是改源码、保存、刷新、再改的死循环。

### 强制伪类状态

Styles 面板的 `:hov` 按钮可以强制元素进入 `:hover`、`:focus` 等状态——不用真的把鼠标悬停着来调试悬停样式。

### 盒模型图

Styles 面板底部（或 Computed 标签页）的彩色盒模型图，实时显示选中元素的 content/padding/border/margin 尺寸。**排查“间距不对”问题先看这里。**

## Console 面板：错误的第一现场

红色报错信息大多与 JavaScript 相关，但也包括：资源 404（图片路径错了）、CORS 错误等。**页面行为不对时，先看 Console 有没有红字。**

## Network 面板：每一个请求的账本

刷新页面，这里列出加载的每个文件：

- **红色行**：加载失败。图片不显示？查这里，八成是 404 路径错误。
- 点击请求可以看详情：完整 URL、状态码、响应内容。
- 顶部可以模拟慢速网络，体验用户在弱网下的加载过程。

## 设备工具栏：移动端模拟

`Ctrl + Shift + M` 切换设备模拟，测试响应式必备（详见[响应式设计](/concepts/responsive)）。

## 高频调试场景速查

| 症状 | 排查路径 |
| --- | --- |
| 样式没生效 | 选中元素 → Styles：选择器命中了吗？被划横线了吗？属性名黄色警告吗？ |
| 间距和预期不符 | 盒模型图 → 谁的 margin/padding 在作怪？记得外边距合并 |
| 图片不显示 | Console/Network 找红色 404 → 核对路径 |
| 元素位置诡异 | Styles 查 position/float；Layout 面板打开 flex/grid 叠加层 |
| 出现横向滚动条 | 从 body 开始逐层检查谁的宽度溢出（选中元素时页面会高亮它的占位） |
| 改了 CSS 文件没变化 | 强制刷新 `Ctrl + F5`（缓存问题）；确认改的是被引用的那个文件 |

## 把 DevTools 变成学习工具

打开任何你觉得好看的网站 → 右键检查它的导航栏/卡片/按钮 → 看它的 HTML 结构和 CSS 写法。**全世界的网页源码都是你的教材。** 配合 AI 使用效果更佳：把看不懂的 CSS 规则复制给 AI，让它逐行解释。

## 练习

1. 打开一个电商网站，用 DevTools 把首页 banner 的标题文字改成你的名字，截图留念（刷新就还原，这是无害的）。
2. 回到你自己的练习页，用 `:hov` 强制查看所有悬停效果；用盒模型图测量导航栏的实际高度。
3. 故意把一张图片的路径改错，完整走一遍排查流程：Console 看报错 → Network 找红色请求 → 修复路径 → 验证。
