# 语义化 HTML

“语义化”指**用含义正确的标签描述内容**，而不是所有东西都用 `<div>` 装。这是区分“会写 HTML”和“写得专业”的分水岭。

## 为什么重要

1. **可读性**：`<nav>` 一眼就知道是导航，`<div class="nav">` 需要靠命名猜。
2. **SEO**：搜索引擎依赖语义标签理解页面结构，影响收录和排名。
3. **可访问性（Accessibility）**：读屏软件靠语义标签为视障用户导航页面。
4. **面试**：“谈谈 HTML 语义化”是前端面试的常客。

## 页面级语义标签

一个典型页面的骨架：

```html
<body>
  <header>
    <h1>网站标题</h1>
    <nav>
      <ul>
        <li><a href="/">首页</a></li>
        <li><a href="/blog">博客</a></li>
        <li><a href="/about">关于</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <article>
      <h2>文章标题</h2>
      <p>文章正文……</p>
    </article>

    <aside>
      <h3>相关推荐</h3>
      <ul>
        <li><a href="#">另一篇文章</a></li>
      </ul>
    </aside>
  </main>

  <footer>
    <p>© 2026 某某网站</p>
  </footer>
</body>
```

| 标签 | 含义 | 使用要点 |
| --- | --- | --- |
| `<header>` | 页眉：标题、Logo、导航 | 页面和 article 内都可以用 |
| `<nav>` | 导航链接区 | 只用于主要导航，不是所有链接堆都算 |
| `<main>` | 页面主体内容 | **每页只能有一个** |
| `<article>` | 独立成篇的内容 | 判断标准：单独拿出去（如 RSS 订阅）仍然完整 |
| `<section>` | 主题性的内容分区 | 通常应该有自己的标题 |
| `<aside>` | 侧边、补充内容 | 广告、相关链接、作者简介 |
| `<footer>` | 页脚：版权、备案、联系方式 | |

## div 汤 vs 语义化

同一个结构的两种写法：

```html
<!-- ❌ div 汤（div soup）：机器和人都难以理解 -->
<div class="header">
  <div class="nav">...</div>
</div>
<div class="content">...</div>
<div class="footer">...</div>

<!-- ✅ 语义化：结构一目了然 -->
<header>
  <nav>...</nav>
</header>
<main>...</main>
<footer>...</footer>
```

`<div>` 并没有被废除——当**确实没有合适的语义标签**、只是需要一个布局容器时，用 `<div>` 完全正确。原则是：**先想有没有语义标签可用，没有再用 div**。

## section 还是 div？

- 内容是一个有主题的“章节”，通常配有标题 → `<section>`
- 纯粹为了布局或样式打包 → `<div>`

## 可访问性的最低要求

即使是初学者，也应该做到：

1. 所有有意义的图片写 `alt`（见[图片](/html/links-images)）。
2. 所有输入框有关联的 `<label>`（见[表单](/html/forms)）。
3. 标题层级不跳级，每页一个 `<h1>`。
4. 链接文字有意义：写“查看课程详情”，不要写“点击这里”。
5. 不要只用颜色传达信息（红色=错误时，同时给出文字提示）。

::: tip 检验方法
做完页面后，把 CSS 全部去掉（或在 DevTools 里禁用样式），页面是否仍然像一份结构清晰的文档？如果是，你的 HTML 就写得不错。
:::

## 练习

1. 把你之前写的个人简介页重构为语义化结构：`header`（姓名 + 导航）、`main`（若干 `section`：教育经历、技能、爱好）、`footer`（联系方式）。
2. 找一个你常逛的网站，右键“检查”，看看它的头部、导航、主体用了什么标签。是语义化的还是 div 汤？
3. 向 AI 要一段“某活动宣传页”的 HTML，检查它的语义化程度并列出你认为可以改进的 3 个点——这是你第一次给 AI 做代码审查。
